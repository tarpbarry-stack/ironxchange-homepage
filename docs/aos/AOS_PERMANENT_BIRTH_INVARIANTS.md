# AOS Permanent Birth Invariants

1. A draft is not a permanent Object.
2. Permanent creation requires a customer-supplied non-placeholder display name.
3. One stable intent key maps idempotently to one permanent birth.
4. Permanent success requires one Object ID and one matching Passport ID.
5. TRAN$ACT eligibility must reference that same Object ID and Passport ID.
6. The returned Object must belong to the authenticated/requested Entity.
7. Creation channel is recorded as provenance and never becomes business taxonomy.
8. Bulk rows succeed or fail independently; successful identities are never recreated on retry.
9. A permanent Object returned by IX-Core replaces temporary client identity; clients do not manufacture a second permanent identity.
10. All future creation channels must terminate at the same provisioning contract or fail CI architecture verification.
